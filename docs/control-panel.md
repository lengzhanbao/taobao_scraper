# 本地采集控制台（2.6）

控制台运行在 `http://127.0.0.1:8765`。不需要安装网页框架，不会把数据上传到网站。

## 打开与使用

已有 Python 和爬虫依赖时，双击 `scripts/open_control_panel.vbs`。
也可以运行：

```powershell
python -B scripts/control_panel.py --open
```

1. 填写数据目录和 Python、Edge、FFmpeg、FFprobe 的完整路径，并保存设置。
2. 在“直播网址管理”选择实例，加载清单，可编辑、批量追加或导入 TXT，再保存。
3. 调整每段时长上限、同房间冷却、批量归档阈值、实例启动间隔。也可点击研究常用配置或短录配置，再检查实例开关。
4. 在实例表调整开关和每房间目标段数，点击“保存设置”。
5. “检查环境”通过后，点击“启动采集”。首次登录在新开的 Edge 中完成，最多等待 5 分钟。
6. 停止时点击“录完当前段后停止”。关闭网页、启动器或命令行窗口不影响已启动的采集进程。

不提供强制停止或数据删除按钮。控制台只管理由自己启动的进程。

## 默认与范围

| 参数 | 默认 | 可设置范围 |
|---|---:|---:|
| 每段时长上限 | 20 分钟 | 1—120 分钟 |
| 同房间冷却 | 120 分钟 | 1—1440 分钟 |
| 批量归档 | 每实例 6 间满段房间 | 任意正整数；设 1 即单个满段房间归档 |
| 启动间隔 | 45 秒 | 0—300 秒 |
| 每房间段数 | 实例 1、2、3、5 为 3；实例 4 为 4 | 1—20 |

设置只影响下一次启动。运行中的任务使用启动时的快照。
FFmpeg 使用 `-t` 限制视频时长；启动连接和页面检查另有耗时。
视频有效时长通过 FFprobe 读取；本版本有效段最低时长为 `min(420秒, 上限秒数 × 0.9)`。
短视频、接流失败、响应日志写入失败、final JSON 写入失败均保留文件，不增加有效段计数。

## 数据与计数

- 录制启动仅读取 `_config/urls_1.txt` 至 `urls_5.txt`，按 liveId 去重，实例间待录链接重复会阻止启动。页面明确点击保存网址时才修改源清单，并先保存原文件完整备份。
- 每次启动创建 `_control/runs/<运行编号>/`，保存设置快照、独立 URL 清单、状态、日志和停止请求。
- 新版录制进度另存于 `<数据目录>/_control/progress_<端口>.json`，重启控制台后继续读取。
- 页面上的历史计数来自旧 URL 清单，**不表示旧视频已经重新验证**。
- 技术有效段数必须来自 FFprobe 实测时长、SHA256 和仍匹配的视频/final JSON 凭据，或通过成套核验的归档；没有这些证据时显示“未核验”。部分房间已核验时，汇总进度标注“至少”，并显示未核验房间数。
- 调整目标段数不删除旧段、不自动重编旧归档。若已有 session 缺段，程序提醒人工核对。
- 未满批量阈值的房间保留在 staging；达到用户设置的正整数阈值才解析。阈值为 1 时允许单个满段房间归档。
- 首次打开面板、读取状态或检查环境，都不会启动爬虫或解析现有视频。

## 页面管理网址

- 选择 Edge 1—5、点击加载清单，页面显示对应文件路径、网址文本和已保存房间的进度。
- 每行填写一个带 liveId 的淘宝直播网址，或纯数字直播 ID。支持旧清单“已录制 n/m”格式；无效行会提示具体行号，整次操作不保存。
- 编辑区保存替换当前启用清单；被移出的行转为停用历史注释，原始内容仍保留。追加区合并现有启用网址，按直播 ID 去重，保留最高已有计数。
- TXT 导入填入追加区，点击添加后才写入文件；单次输入最多 48 KB。导出下载的是编辑区当前草稿，下载位置由浏览器决定。
- 每次修改已有文件前生成同目录 `urls_N.txt.bak_<SHA256>` 备份；相同文件内容只备份一次。停用历史按直播 ID 去重；不同历史版本仍保留，不自动删除。
- 原文件被其他程序修改后拒绝覆盖，保留页面草稿。可以先导出草稿，再点恢复已保存清单重新加载。切换实例前要求保存编辑区草稿。
- 运行期间编辑网址只影响下次启动；当前任务使用独立清单快照。网址编辑与修改录制设置分别保存。
- “核对后更正历史计数”只改指定直播间的计数，并同步修正该 ID 的停用历史注释；会先备份原清单，再把原因和更正前后计数追加到 `<数据目录>/_control/url_count_corrections.jsonl`。更正值不能低于已核验/已归档段数；旧 `progress.json` 计数不会覆盖更正，之后新写入的进度会正常生效。
- 旧版后台继续运行时页面禁用新增网址 API。需要结束当前任务、重启控制台才能使用新版功能；刷新页面不会更新后台程序。

## 数字人规则

本次当前直播 ID 的 detail 响应全 true 时录制；包含 false 或缺失时跳过。
标题包含“虚拟主播”或“智能主播”时按用户规则录制，原始平台 true/false 单独保留。
录制期间可能切换主播，因此 parser 仍需依据整段响应标记全 true、含 false、缺失。
平台 false 的记录应复核；不能单凭此字段认定真人。

## 本次可靠性更新

- 启动不删除未完成段；重试创建独立 attempt 目录和独立视频文件。
- 失败视频、日志、JSONL 原始响应全部保留；不使用 ffmpeg `-y` 覆盖原视频。
- final JSON 原子写入完成后才允许增加有效段计数。
- 每条响应追加到 JSONL，避免只有最后 800 条响应；缓存序号独立递增。
- 新段保存 recording_id、segment_index、实际视频时长及首批视频数据时间。
- 归档逐个核对 JSON/视频 SHA256，生成 `archive_manifest.json`。现有不同内容的目标文件会触发冲突，保留两端文件。
- 归档完成后保留全部 staging 源文件；重写 CSV 前另存备份。
- URL 收集器不再按进程名全局关闭 Edge/ffmpeg。
- 缺 Cookie 时等待浏览器登录；后台运行不使用 `input()`。
- 可通过 `LIVE_STAGING_ROOT` 将暂存视频写入单独目录；`LIVE_COOKIE_JSON` 可指定只读登录 Cookie 文件，配合 `LIVE_SAVE_COOKIES=0` 禁止刷新/重写该文件。这些覆盖项用于隔离式验收，面板平常使用数据目录默认值。
- 程序持有端口文件锁；控制台记录 PID 和进程创建时间，避免将复用 PID 当作原任务。

Cookie 完全过期后仍可能需要人工登录。网页中显示等待登录、超时和进程退出状态，不保证自动续期。

## 录制进度与实例暂停

- 总进度和每实例进度按已验证有效段显示“有效段数 / 总目标段数”、百分比及进度条。历史计数单独显示；没有有效凭据的旧段不占有效进度。
- 当前正在录制的段显示运行时间 / 时长上限进度。校验成功且 final JSON 写入后才增加有效段计数；时间条达到上限不代表视频已通过校验。
- 运行中的实例按本次启动快照计算进度，修改下次启动的设置不会改变当前任务的目标和数据目录。
- 各实例的“暂停”只控制该实例：录制中先录完当前段，保留并计入通过校验的段，再暂停；冷却等待会立即进入暂停，扫描页面则完成当前检查后暂停。
- “继续”恢复原任务，保留同房间冷却和已录段数。暂停请求尚未生效时也可点击继续取消请求。
- 暂停先于下一批归档；已开始的归档会完成后再暂停。满段房间留在队列，继续后按原阈值归档。
- 已暂停的实例可使用全局“录完当前段后停止”退出。恢复时将控制文件改写为 paused=false，不删除暂停文件。
- 已经由 2.1 启动的任务不支持新增暂停协议；需先在原面板请求停止并等待退出，再关闭旧控制台进程、重新打开控制台后启动新任务。仅刷新页面不会更新后台服务。
- 升级不自动中断已有任务，也不改变已有录制设置。默认归档阈值继续为 6，用户可保存任意正整数。

## 版本 2.4 计数说明

- 历史计数来自网址清单或旧格式进度文件，仍用于恢复任务，但不再冒充有效段。
- 新版有效计数须有录制成功写入的 final JSON 凭据，且凭据路径、录制 ID、时长和视频文件大小/修改时间仍匹配。
- 已归档计数依据归档 manifest；目标文件仍存在且字节数匹配时按唯一 recording ID 计数。
- 缺少新版已知设置项时会用默认值补齐并先备份旧设置；未知设置项或损坏 JSON 会停止加载并保留原件。
- 仅当端口已有服务的版本和代码根目录都与当前安装完全相同，才打开该服务；旧版本会显示 PID 与版本提示。

## 版本 2.5 计数与连接状态

- 如果所有房间都缺少有效凭据，`valid_segments` 和有效完成进度为 `null`，页面显示“未核验”；历史计数仍单独显示，并继续用于续录位置。
- 有一部分房间已核验时，页面只汇总有证据的段数并标注“至少 N 段”，同时列出未核验房间数，不把未知段当成有效段。
- 状态接口连续两次刷新失败后，页面提示控制台连接中断、显示最后成功同步时间，并将后台采集进程状态标为未知；不据此断言子进程已停止。
- 历史计数纠错需要核验勾选和原因；下调时再弹出确认。纠错事件只追加，不自动清理；源网址文件备份保留。

## 版本 2.6：实测时长、标记与成套归档

- 页面分开显示技术有效段、已捕获标记全 true / 非全 true、完整归档段。仅记录标记，不新增严格样本分类或覆盖阈值；标题规则继续沿用并单独保留关键词。
- 页面标记数量汇总已核验的技术有效段；失败段也在 attempt_status 中保留已捕获标记，但不计入录制完成数。
- 全 true 仅指可明确关联当前 liveId 的已捕获 detail 响应中的标记；未捕获可识别标记时注明缺失，非全 true 不直接解释为真人。保存标记数量、缺失响应数、录制期间检测次数及最大检测空窗；这些点状观察不证明整个时段连续全 true。
- 新 final JSON 保存 FFprobe 实测时长、最低时长、视频 SHA256 与核验来源；进度凭据另存 final JSON 的 SHA256。没有新版实测凭据的旧段保留历史计数，显示未核验。
- parser 在复制前实测所有对应视频，不使用 JSON 时间戳差判断时长。CSV 的总录制时长改用实际媒体时长；原录制起止时间戳原样保留。
- 新归档清单为 schema 2，逐段绑定 raw JSON、FLV、弹幕 CSV 和包含唯一录制 ID 的汇总行；核对文件 SHA256、视频实测时长、录制 ID 和段号。旧清单缺少成套凭据时提示待核查，不自动补造凭据。
- 弹幕状态分别记录 extracted、empty_confirmed、not_captured、parse_failed；有效的空弹幕 CSV 可通过核验。未捕获响应不等于直播没有弹幕；提取失败不计为完整核验归档。
- 页面 GET 请求 10 秒超时、修改请求 90 秒超时；状态请求串行，连续两次失败后标记断线，自动轮询恢复。修改请求超时不自动重试，并提示后台可能已经完成。
- 哈希与视频探测结果按文件路径、大小、修改时间和创建/变更时间缓存；文件改变后重新核验，归档统计最多有 30 秒缓存延迟。

## 历史 7 分钟段核验

`finalize_7min_segments.py` 默认只递归读取 staging（包括 attempt 子目录及已有 final JSON），在项目 `_control/recovery_reports/<唯一编号>/audit.json` 写独立报告。实际视频不足 420 秒的段不通过；房间已有 sessions 也不会整间跳过。

显式加 `--create-finals` 时，仅在新报告目录的 candidates 子目录生成合格候选 JSON；不写回 staging、不修改原录制起止时间、不更新网址或进度。响应完整性、录制起点或段号凭据不足时只报告，候选不生成。候选文件不会自动计入采集器进度。

本次没有批量处理真实历史数据。正式核验历史数据时先查看报告，再决定如何使用候选。

旧 `detect_digital_20260806.py` 已转为共用检测器入口，汇总一次检测窗口的全部相关响应和标记；短检测结果不代表随后整段录制的标记。
