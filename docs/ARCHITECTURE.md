# 项目架构说明

## 总体架构

```
┌─────────────────────────────────────────────────────────┐
│                    用户交互层                              │
│  scripts/   (启动脚本、数据处理脚本)                       │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                    核心业务层                              │
│  src/                                                    │
│  ├── crawler/     爬虫引擎                                │
│  ├── parser/      数据解析                                │
│  ├── detector/    数字人检测                              │
│  └── utils/       工具模块                                │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                    数据存储层                              │
│  直播研究数据/                                             │
│  ├── _config/     配置文件                                │
│  ├── _staging/    暂存数据                                │
│  └── sessions/    归档数据                                │
└─────────────────────────────────────────────────────────┘
```

## 模块详解

### 1. Crawler 模块

**职责:** 直播间监控和录制

**核心功能:**
- 浏览器自动化 (DrissionPage)
- 网络请求拦截
- 视频流录制 (FFmpeg)
- 弹幕实时抓取
- 商品信息采集

**关键类/函数:**
- `scan_room()` - 扫描直播间状态
- `record_room()` - 录制直播间
- `solve_slider()` - 滑块验证码破解
- `drain_responses()` - 网络响应收集

### 2. Parser 模块

**职责:** 数据解析和归档

**核心功能:**
- JSON数据解析
- CSV格式导出
- 视频文件管理
- 去重和数据清洗

**关键类/函数:**
- `process_room()` - 处理单个房间数据
- `write_csv()` - CSV写入（去重）
- `strip_jsonp()` - JSONP格式解析
- `deep_find()` - 深度搜索JSON

### 3. Detector 模块

**职责:** 数字人检测

**核心功能:**
- 批量URL发现
- 数字人标识检测
- 自动化收集

**关键类/函数:**
- `collect_digital.py` - URL收集器
- `detect_digital.py` - 检测脚本

### 4. Utils 模块

**职责:** 配置和工具

**核心功能:**
- 环境变量管理
- 路径配置
- 状态更新

**关键文件:**
- `config.py` - 配置管理
- `update_urls.py` - URL状态更新

## 数据流程

```
1. 启动爬虫
   ↓
2. 读取URL配置 (urls_1.txt ~ urls_5.txt)
   ↓
3. 随机选择直播间
   ↓
4. 扫描直播间状态
   ↓
5. 录制20分钟视频 + 抓取数据
   ↓
6. 保存到 _staging/browser_<port>/room_<liveId>/
   ↓
7. 标记已录制，冷却2小时
   ↓
8. 达到目标轮次后解析数据
   ↓
9. 归档到 sessions/<店铺名>_<liveId>/
```

## 多实例架构

```
实例1 (端口9223)  →  urls_1.txt  →  .edge_9223/  →  browser_9223/
实例2 (端口9224)  →  urls_2.txt  →  .edge_9224/  →  browser_9224/
实例3 (端口9225)  →  urls_3.txt  →  .edge_9225/  →  browser_9225/
实例4 (端口9226)  →  urls_4.txt  →  .edge_9226/  →  browser_9226/
实例5 (端口9227)  →  urls_5.txt  →  .edge_9227/  →  browser_9227/
```

每个实例：
- 独立浏览器Profile
- 独立调试端口
- 独立输出目录
- 独立URL队列

## 关键技术

### 浏览器自动化
- **库:** DrissionPage
- **浏览器:** Microsoft Edge (推荐) / Chrome
- **优势:** 绕过反爬、保持登录态

### 视频录制
- **工具:** FFmpeg
- **格式:** FLV (直播流原生格式)
- **策略:** 20分钟/段，自动分段

### 数据采集
- **方法:** 网络请求拦截
- **API:** mtop.taobao.com
- **数据:** 直播详情、商品信息、弹幕

### 防封禁
- **随机延迟:** 180-300秒
- **冷却机制:** 2小时
- **人性化操作:** 滑块验证、鼠标轨迹
- **Cookie管理:** 自动续期

## 扩展性设计

### 添加新的数据源
1. 在 `src/crawler/` 创建新爬虫模块
2. 继承基础配置
3. 实现自定义采集逻辑

### 添加新的数据处理
1. 在 `src/parser/` 创建解析模块
2. 实现数据转换逻辑
3. 导出标准格式

### 添加新的检测规则
1. 在 `src/detector/` 扩展检测逻辑
2. 更新检测API
3. 集成到收集流程

## 性能优化

### 内存优化
- 流式处理大文件
- 及时释放响应数据
- 限制历史记录大小

### 磁盘优化
- 定期清理临时文件
- 压缩旧视频
- 归档冷数据

### 并发优化
- 多实例独立运行
- 避免资源竞争
- 错峰启动 (45秒间隔)

## 安全考虑

### 数据安全
- Cookie加密存储
- 敏感信息脱敏
- 访问权限控制

### 合规性
- 遵守robots.txt
- 限制采集频率
- 仅用于研究
